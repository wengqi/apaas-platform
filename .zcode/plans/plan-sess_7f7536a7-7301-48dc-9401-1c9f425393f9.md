# 流程引擎样式修复计划 — 对齐 flowgram.ai 官方最佳实践

## 根因分析

通过对 flowgram.ai 官方最佳实践源码和我们当前实现的深度对比，发现以下 6 个关键偏差导致样式问题：

| # | 最佳实践 | 当前实现 | 影响 |
|---|---------|---------|------|
| 1 | 条件节点 `extend: 'dynamicSplit'` | 无 `extend`，手动 `onCreate` | **布局引擎不使用 DynamicSplitRegistry 的居中几何计算**，导致节点偏移、连线不垂直 |
| 2 | 分支子节点 `extend: 'block'` | 无注册表 | 分支容器不被识别为 block 类型 |
| 3 | 不覆盖几何常量（默认 NODE_SPACING=32, ROUNDED_LINE_RADIUS=16） | `SPACING: 60, ROUNDED_LINE_RADIUS: 0, BRANCH_SPACING: 40` | 破坏了默认的连线和间距计算 |
| 4 | `...defaultFixedSemiMaterials` 展开，仅覆盖 ADDER | 手动注册所有渲染器，用 NoopRenderer 替换 Collapse | 丢失了默认的 Collapse/分支渲染器 |
| 5 | 不设 `meta.size`（继承 DEFAULT_SIZE 280x60） | 所有节点设 `size: {width: 240}` | 布局引擎期望 280px 但渲染 240px |
| 6 | `renderDefaultNode: BaseNode` | `FlowRendererKey.NODE_RENDER` | 注册方式不同 |
| 7 | 无 `transform` 补偿 | `transform: translateX(40px)` | 视觉移动但不更新连线连接点 |

## 修改方案

### 1. `nodes/condition/index.ts` — 添加 `extend: 'dynamicSplit'`
```ts
export const ConditionNodeRegistry: FlowNodeRegistry = {
  type: 'condition',
  extend: 'dynamicSplit',  // 关键！让 flowgram 使用 DynamicSplitRegistry 的居中布局
  meta: {
    expandable: false,
  },
  formMeta: ConditionFormMeta,
  // 不需要自定义 onCreate — DynamicSplitRegistry.onCreate 自动调用 addInlineBlocks
  // 不需要自定义 meta.size — 继承 DEFAULT_SIZE (280x60)
};
```

### 2. `nodes/index.ts` — 删除 BlockIconOverrideRegistry
- 删除 `BlockIconOverrideRegistry`（覆盖 blockIcon size 导致布局问题）
- 使用 flowgram 默认的 BlockIconRegistry（size: 250x84, spacing: 20）
- blockIcon 的渲染由 `defaultFixedSemiMaterials` 的默认渲染器处理

### 3. 所有节点注册表 — 删除 `meta.size`
- `start/index.ts`, `end/index.ts`, `trigger/index.ts`, `object-operation/index.ts`, `condition/index.ts`, `user-task/index.ts`, `notification/index.ts`, `http-request/index.ts`, `assign/index.ts`, `delay/index.ts`
- 删除所有 `size: { width: 240, height: 52 }` — 让节点继承 DEFAULT_SIZE (280x60)
- 保留其他 meta 字段（isStart, deleteDisable 等）

### 4. `SimplifiedEditor.tsx` — 对齐最佳实践配置

#### 4a. materials 配置
```ts
materials: {
  components: {
    ...defaultFixedSemiMaterials,           // 展开默认材质
    [FlowRendererKey.ADDER]: ApaasAdder,    // 仅覆盖加号按钮
    // 不覆盖 BRANCH_ADDER, COLLAPSE, DRAG_NODE 等 — 使用默认
  },
  renderDefaultNode: ApaasNodeRenderer,     // 用 renderDefaultNode 而非 NODE_RENDER
},
```

#### 4b. constants 配置
```ts
constants: {
  // 不设置 SPACING, ROUNDED_LINE_RADIUS, BRANCH_SPACING — 使用默认值
  BASE_COLOR: '#B8BCC1',
  BASE_ACTIVATED_COLOR: '#82A7FC',
},
```

#### 4c. nodeEngine
```ts
nodeEngine: { enable: true },  // 启用节点引擎（form 渲染依赖）
```

#### 4d. ApaasNodeRenderer — 简化
- 删除 `transform: translateX(40px)` 补偿（不再需要）
- 删除系统节点处理（blockIcon/blockOrderIcon 由默认渲染器处理）
- 删除外层+内层 div 嵌套，使用单层 div + 固定宽度
- 节点宽度使用固定值（如 240px），与最佳实践一致

#### 4e. CSS overlay 覆盖
- 保留对 `gedit-flow-lines-layer` 和 `gedit-selector-bounds-*` 的 `pointer-events: none` 覆盖
- 删除对 `gedit-flow-labels-layer` 的覆盖（adder 在该层中）

### 5. 添加 Semi UI CSS
- 在 `index.html` 中通过 `<link>` 引入 Semi UI CSS
- 或在 `SimplifiedEditor.tsx` 中 import（需解决 Vite 解析问题）

## 不修改的文件
- `NodePanel.tsx` — 左侧面板不变
- `NodeConfigPanel.tsx` — 配置面板不变
- `stores/processEditor.ts` — store 不变
- `schema-serializer.ts` — 序列化器不变
