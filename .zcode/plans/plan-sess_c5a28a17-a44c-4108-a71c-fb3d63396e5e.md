# aPaaS Docker 部署方案

## 架构总览

```
┌─────────────────────── Docker Network ───────────────────────┐
│                                                              │
│  ┌────────────┐   ┌────────┐   ┌──────────────────────────┐ │
│  │ PostgreSQL │   │ Redis  │   │  API Gateway (NestJS)     │ │
│  │  :5432     │   │ :6379  │   │  :3000                    │ │
│  └────────────┘   └────────┘   │  entrypoint:              │ │
│                                 │   ① 等 DB 就绪            │ │
│  ┌──────────────────┐          │   ② prisma migrate deploy │ │
│  │ Studio (nginx)   │          │   ③ seed (幂等)           │ │
│  │  :80 → :8080     │──/api──▶│   ④ node dist/main.js     │ │
│  │  Vite 静态文件   │          └──────────────────────────┘ │
│  └──────────────────┘                   ▲                    │
│                                         │                    │
│  ┌──────────────────┐                   │                    │
│  │ Runtime UI (nginx│──/api──────────────┘                   │
│  │  :80 → :8081     │                                        │
│  │  Vite 静态文件   │                                        │
│  └──────────────────┘                                        │
└──────────────────────────────────────────────────────────────┘

宿主机访问：
  Studio     →  http://localhost:8080
  Runtime UI →  http://localhost:8081
  API        →  http://localhost:3000 (直连，调试用)
  PostgreSQL →  localhost:5432 (调试用)
  Redis      →  localhost:6379 (调试用)
```

**核心设计**：前端 nginx 同时托管静态文件 + 反向代理 `/api` → gateway，实现同源访问，无需 CORS。

## 详细实现

### 1. `.dockerignore`

排除不需要的文件，减小构建上下文：

```
node_modules/
dist/
build/
.next/
.turbo/
*.tsbuildinfo
.git/
.env
.env.local
.env.*.local
docs/
infra/data/
coverage/
.DS_Store
*.log
```

> 注意：保留 `.env.example`（不排除），排除 `.env`（避免 Vite 构建时读取 dev 配置的 `VITE_API_BASE_URL=http://localhost:3000`，确保前端使用相对路径默认值）。

### 2. `Dockerfile`（多阶段构建）

```dockerfile
# ============================================================
# aPaaS Dockerfile — 多阶段构建
# Targets: gateway, studio, runtime-ui
# 用法: docker build --target <target> -t apaas-<target> .
# ============================================================

# ---- Base: Node.js 20 + pnpm ----
FROM node:20-alpine AS base
RUN apk add --no-cache libc6-compat
RUN corepack enable
WORKDIR /app

# ---- Deps: 安装全部依赖（利用 Docker 层缓存）----
FROM base AS deps
RUN apk add --no-cache python3 make g++   # bcrypt 原生编译兜底
# 先复制所有 package.json + workspace 配置（依赖不变时命中缓存）
COPY pnpm-lock.yaml pnpm-workspace.yaml package.json ./
COPY apps/gateway/package.json apps/gateway/
COPY packages/db/package.json packages/db/
COPY packages/shared/package.json packages/shared/
COPY packages/studio/package.json packages/studio/
COPY packages/runtime-ui/package.json packages/runtime-ui/
COPY packages/studio/features/process/simplified/package.json \
     packages/studio/features/process/simplified/
RUN pnpm install --frozen-lockfile

# ---- Builder: 构建全部包 ----
FROM deps AS builder
COPY . .
# 生成 Prisma Client
RUN pnpm --filter @apaas/db run generate
# Turbo 按依赖顺序构建（shared → db → gateway / studio / runtime-ui）
RUN pnpm build

# ============== Gateway 运行时 ==============
FROM base AS gateway
ENV NODE_ENV=production
# 复制构建产物 + 依赖（含 pnpm 符号链接结构、Prisma 生成客户端）
COPY --from=builder /app .
COPY infra/entrypoint-gateway.sh /entrypoint.sh
RUN chmod +x /entrypoint.sh
EXPOSE 3000
ENTRYPOINT ["/entrypoint.sh"]

# ============== Studio 前端（nginx） ==============
FROM nginx:alpine AS studio
COPY --from=builder /app/packages/studio/dist /usr/share/nginx/html
COPY infra/nginx/app.conf /etc/nginx/conf.d/default.conf
EXPOSE 80

# ============== Runtime UI 前端（nginx） ==============
FROM nginx:alpine AS runtime-ui
COPY --from=builder /app/packages/runtime-ui/dist /usr/share/nginx/html
COPY infra/nginx/app.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
```

**说明**：
- `deps` 阶段仅复制 package.json 文件 → 依赖不变时走 Docker 缓存，秒级完成
- `builder` 阶段复制源码 + 构建（turbo 自动处理依赖顺序）
- `gateway` 运行时复制完整 `/app`（含 node_modules 符号链接 + dist + Prisma 客户端 + 迁移文件），确保 `prisma migrate deploy` 和 `tsx seed.ts` 可用
- `studio`/`runtime-ui` 运行时仅含 Vite 构建的静态文件 + nginx，镜像极小
- 前端构建时 `.env` 被 `.dockerignore` 排除 → `VITE_API_BASE_URL` 为 undefined → Studio baseURL 默认 `""`（相对路径）、Runtime UI baseURL 默认 `"/api"` → nginx 同源代理

### 3. `docker-compose.yml`（根目录）

```yaml
# ============================================================
# aPaaS 全量 Docker 部署
# 用法: docker compose up -d --build
# ============================================================

services:
  # ---------- 基础设施 ----------
  postgres:
    image: postgres:16-alpine
    container_name: apaas-postgres
    restart: unless-stopped
    environment:
      POSTGRES_USER: apaas
      POSTGRES_PASSWORD: apaas
      POSTGRES_DB: apaas
      TZ: Asia/Shanghai
    ports:
      - "5432:5432"
    volumes:
      - apaas_pg_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U apaas -d apaas"]
      interval: 5s
      timeout: 5s
      retries: 10
      start_period: 10s

  redis:
    image: redis:7-alpine
    container_name: apaas-redis
    restart: unless-stopped
    command: ["redis-server", "--appendonly", "yes"]
    ports:
      - "6379:6379"
    volumes:
      - apaas_redis_data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 10
      start_period: 5s

  # ---------- 后端 API 网关 ----------
  gateway:
    build:
      context: .
      dockerfile: Dockerfile
      target: gateway
    container_name: apaas-gateway
    restart: unless-stopped
    environment:
      NODE_ENV: production
      DATABASE_URL: postgresql://apaas:apaas@postgres:5432/apaas?schema=public
      REDIS_URL: redis://redis:6379
      JWT_SECRET: ${JWT_SECRET:-dev-secret-change-me-in-production-use-long-random-string}
      JWT_EXPIRES_IN: ${JWT_EXPIRES_IN:-7d}
      GATEWAY_PORT: "3000"
      CORS_ORIGINS: "http://localhost:8080,http://localhost:8081"
    ports:
      - "3000:3000"
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy

  # ---------- 前端：Studio 搭建器 ----------
  studio:
    build:
      context: .
      dockerfile: Dockerfile
      target: studio
    container_name: apaas-studio
    restart: unless-stopped
    ports:
      - "8080:80"
    depends_on:
      - gateway

  # ---------- 前端：Runtime UI 运行时 ----------
  runtime-ui:
    build:
      context: .
      dockerfile: Dockerfile
      target: runtime-ui
    container_name: apaas-runtime-ui
    restart: unless-stopped
    ports:
      - "8081:80"
    depends_on:
      - gateway

volumes:
  apaas_pg_data:
    name: apaas_pg_data
  apaas_redis_data:
    name: apaas_redis_data
```

**关键点**：
- PG/Redis 使用 `healthcheck` + `depends_on: condition: service_healthy`，确保 gateway 启动时 DB 已就绪
- `DATABASE_URL`/`REDIS_URL` 使用 Docker 内部服务名（`postgres`/`redis`）
- `JWT_SECRET` 可通过宿主机 `.env` 或环境变量覆盖
- `CORS_ORIGINS` 设置为前端访问地址（虽 nginx 同源代理不触发 CORS，但保留直连 API 的能力）
- 前端 nginx 将 `/api` 代理到 `gateway:3000`（Docker 内部网络）

### 4. `infra/nginx/app.conf`

```nginx
server {
    listen 80;
    server_name _;

    root /usr/share/nginx/html;
    index index.html;

    # SPA 路由 fallback（React Router history 模式）
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理 → Gateway
    location /api {
        proxy_pass http://gateway:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Studio 和 Runtime UI 共用此配置（均托管在 `/usr/share/nginx/html`，nginx 容器内服务名 `gateway` 可解析）。

### 5. `infra/entrypoint-gateway.sh`

```bash
#!/bin/sh
set -e

echo "🔄 aPaaS Gateway 启动中..."

# ① 等待 PostgreSQL 就绪（Node.js net 模块检测，无需额外安装）
echo "⏳ 等待 PostgreSQL..."
node -e "
const net = require('net');
const host = process.env.PG_HOST || 'postgres';
const port = parseInt(process.env.PG_PORT || '5432');
function check() {
  const conn = net.connect(port, host);
  conn.on('connect', () => { conn.end(); process.exit(0); });
  conn.on('error', () => setTimeout(check, 1000));
}
check();
"

# ② 执行数据库迁移
echo "📦 执行 Prisma 迁移..."
pnpm --filter @apaas/db run migrate:deploy

# ③ 执行种子数据（幂等，重复执行安全）
echo "🌱 执行种子数据..."
pnpm --filter @apaas/db run seed || echo "⚠️  种子数据已存在或跳过"

# ④ 启动 Gateway
echo "🚀 启动 API Gateway..."
exec node apps/gateway/dist/main.js
```

**说明**：
- 使用 Node.js `net` 模块检测 PG 端口（node:20-alpine 自带，无需 `apk add`）
- `prisma migrate deploy`：执行 pending 迁移（生产安全，非 `migrate dev`）
- `seed` 脚本使用 `upsert`，幂等可重复执行；`|| true` 防止已存在时报错阻断启动
- `exec node` 确保信号正确传递（Ctrl-C / docker stop 优雅退出）

### 7. 修改 `apps/gateway/src/main.ts`

将 CORS 从硬编码改为环境变量驱动：

```typescript
// 修改前：
app.enableCors({
  origin: [
    'http://localhost:5173',
    'http://localhost:5174',
  ],
  credentials: true,
});

// 修改后：
const corsOrigins = process.env.CORS_ORIGINS
  ? process.env.CORS_ORIGINS.split(',').map(s => s.trim())
  : ['http://localhost:5173', 'http://localhost:5174']; // dev 默认
app.enableCors({
  origin: corsOrigins,
  credentials: true,
});
```

> Docker 部署中 nginx 同源代理不触发 CORS，此修改仅为保留直连 API 的灵活性。dev 模式行为不变（未设置 `CORS_ORIGINS` 时使用原默认值）。

## 前端 API 路径验证

| 前端 | baseURL 来源 | baseURL 值 | 请求示例 | nginx 代理后 |
|---|---|---|---|---|
| Studio | `VITE_API_BASE_URL ?? ''` | `""` (未设 env) | `GET /api/apps` | → `gateway:3000/api/apps` ✓ |
| Runtime UI | `VITE_API_BASE_URL ?? '/api'` | `"/api"` (未设 env) | `GET /apps` → `/api/apps` | → `gateway:3000/api/apps` ✓ |

> `.dockerignore` 排除 `.env`，Vite 构建时 `VITE_API_BASE_URL` 为 `undefined`，两个前端各自走默认值，nginx 同源代理完美工作。

## 使用方式

```bash
# 一键部署（构建 + 启动）
pnpm docker:up
# 或: docker compose up -d --build

# 查看日志
pnpm docker:logs

# 停止
pnpm docker:down

# 完全清理（含数据卷）
docker compose down -v

# 访问
#   Studio     →  http://localhost:8080
#   Runtime UI →  http://localhost:8081
#   API        →  http://localhost:3000/api/health
#   登录账号   →  admin@apaas.dev / admin123
```

## 与开发模式的区别

| | 开发模式 | Docker 部署 |
|---|---|---|
| 启动命令 | `pnpm infra:up && pnpm dev` | `pnpm docker:up` |
| PG/Redis | Docker 容器 | Docker 容器（同一 compose） |
| 后端 | 本地 `nest start --watch` (热重载) | 容器 `node dist/main.js` |
| 前端 | 本地 `vite` dev server (HMR) | nginx 托管静态文件 |
| API 代理 | Vite dev server proxy | nginx 反向代理 |
| 端口 | 5173 / 5174 / 3000 | 8080 / 8081 / 3000 |
| compose 文件 | `infra/docker-compose.yml` | `docker-compose.yml`（根目录） |
