## 目标

将「禁止定时器轮询」确立为项目编码原则，记录到编码规范约束文件（AGENTS.md）和知识库，并加入 ESLint 约束链做自动化拦截。已确认源码中无 `setInterval` 调用（仅注释提及），机械拦截不破坏现有代码；`setTimeout` 的合法 debounce/defer 用法不受影响。

## 改动清单（4 个文件）

### 1. `AGENTS.md` — 编码规范新增小节

在 `## 编码规范` 下、`### 代码风格` 之后（第 75 行后）插入新小节 `### 实时性与事件驱动（禁止定时器轮询）`：

- 禁止使用定时器轮询（`setInterval` / `setTimeout` 递归轮询循环）作为状态同步、数据刷新或事件监听的实现方式
- 必须使用事件驱动架构替代：框架原生事件 API（flowgram `onSelectionChanged`/`onNodeCreate`/`onNodeDispose`/`onExtInfoChange`）、Pub/Sub、WebSocket、React Query 事件订阅等
- 原因：性能开销、轮询间隔内状态不一致窗口、调试维护困难
- 前车之鉴：流程引擎条件分支 300ms `setInterval` 轮询 → `EventBridge` 事件驱动
- 例外：`setTimeout` 用于 debounce/defer（防抖导出、表单 reset 延迟）；React Query `refetchInterval` 需 PR 说明理由
- ESLint 已用 `no-restricted-syntax` 拦截 `setInterval`，指向知识库条目

### 2. `eslint.config.mjs` — 新增 no-restricted-syntax 规则

在 `rules:` 块（第 31-46 行）内新增，拦截裸 `setInterval(...)` 与 `window.setInterval(...)` / `globalThis.setInterval(...)` 两种形式。`message` 指明替代方案与知识库路径，并声明 `setTimeout` 防抖不受限。规则为 `error` 级，配合现有 `--max-warnings 0` 与 pre-commit/pre-push 钩子强制执行。
