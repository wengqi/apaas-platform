# 飞书 aPaaS 级低代码平台 — 最终实施计划

## 一、平台定位

复刻飞书 aPaaS 四大核心能力（对象/数据建模、可视化页面搭建器、流程引擎、权限与多租户）：

- **流程引擎全面覆盖 BPMN 2.0 规范**（Camunda 8/Zeebe 驱动）
- **流程建模双模式**，且**同源双向自动互转**：
  - 标准模式：bpmn-js（完整 BPMN 2.0 元素）
  - 简化模式（飞书式）：Fork flowgram.ai 深度定制
  - 单一数据源 = BPMN 2.0 XML；简化模式是 BPMN 的受约束子集编辑器；简化→标准始终无损，标准→简化时高级元素降级为只读占位

TypeScript 全栈，独立 Web 应用。

## 二、团队组织与调度模型

### 协调架构（单一主控）

```
项目发起人 (你) ── 决策者: 审批计划、方向决策、阶段性验收
    ▼
主智能体 (我) ── 项目经理 + 技术负责人 (唯一总调度)
    │  ① 进度把控(ROADMAP/TodoWrite) ② 任务拆解与分派
    │  ③ 跨模块整合 ④ 阶段验收 ⑤ 风险与依赖管理
    │  ⑥ 串起"产品→设计→开发→QA"全闸门
    │
    ├── 🎯 产品经理 Agent (按需)        → PRD
    ├── 🎨 UI/UE 设计师 Agent (按需)    → 设计规范
    ├── 🏗 架构师 Agent
    ├── ⚙️ 后端 Agent   🔌 流程 Agent
    ├── 🎨 前端 Agent   🔐 平台 Agent
    └── 🧪 QA Agent
```

**调度模式**：主智能体（我）唯一总调度。子 agent 都是临时任务型，通过 Agent 工具按需启动、完成单一任务后返回结果，不持久、彼此不直接通信，全经我中转协调。对接边界 = `packages/shared` 类型契约 + 产出的 PRD/设计规范文档。

## 五、双模式同源互转机制（核心架构决策）

**单一数据源（SSOT）：BPMN 2.0 XML**。两个模式都读写同一份。

| 方向 | 行为 |
|---|---|
| 简化 → 标准 | **始终无损**（简化只产出 BPMN 子集 = 全集的真子集） |
| 标准 → 简化 | **按元素能力分级**：① 仅含子集元素→简化模式完全可编辑；② 含高级元素(边界事件/补偿/事务/复杂网关/泳道)→简化模式**只读**，高级元素折叠为占位标记，提示"切换标准模式编辑" |

技术实现：`bpmn-bridge` 模块含 `flowgram-to-bpmn`、`bpmn-to-flowgram`、`capability-check`（解析 XML 判定可编辑/只读）。

## 七、四大核心模块详细设计

### 模块 1：对象/数据建模（基石）

- **对象(Object)**：用户定义业务实体，存 `objects` 元数据表
- **字段类型**：文本/数字/日期/单选多选/关联/富文本/公式/自动编号/附件/人员/子表
- **关联关系**：一对多、多对多(中间对象)
- **存储方案**：JSONB 宽表。`records` 表存所有对象记录，`object_id`+`data JSONB`，GIN 索引
- **记录 CRUD**：通用 API，按 `object_id`+元数据校验
- **视图(View)**：列表(筛选/排序/分组/字段显隐)、详情、表单
- **数据集(Dataset)**（后期）：多表聚合

### 模块 2：可视化页面搭建器（最大难点）

- **设计器三栏**：左组件面板 → 中画布(dnd-kit) → 右属性面板（对齐飞书 aPaaS）
- **页面类型**：列表页/详情页/表单页/仪表盘/自定义页
- **组件体系**：容器(页面/分区/标签页/栅格)、数据(表格/表单/详情卡)、表单(输入/下拉/日期/关联选择/子表)、展示(统计卡/图表/富文本) ~20 个起步
- **视图模型(View Model)**：飞书核心概念。页面级状态树，组件属性通过表达式绑定状态节点
- **页面 Schema**：组件树+视图模型+绑定关系元数据 JSON
- **运行时渲染器**：递归解析组件树渲染，解析表达式，调数据 API

### 模块 3：流程引擎（Camunda 8 驱动，BPMN 2.0 全覆盖，双模式同源互转）⭐ 核心

**层 1：执行内核 — Camunda 8 (Zeebe)**
独立部署，负责全部 BPMN 2.0 运行时语义：
- **事件**：Start/Intermediate/End/Boundary 全类型 + 全触发器(Message/Timer/Error/Signal/Compensation/Conditional/Link/Terminate/Escalation/Cancel/Multiple)
- **活动**：Task 全类型(User/Service/Send/Receive/Manual/BusinessRule/Script) + Sub-Process(含 Ad-Hoc/Event Sub-Process) + Call Activity + Transaction + 循环/多实例标记
- **网关**：Exclusive(XOR)/Parallel(AND)/Inclusive(OR)/Event-based/Complex 全类型
- **连接**：Sequence/Message Flow/Association/Conditional/Default Flow
- **泳道**：Pool/Lane/Lane Set(协作图)
- **工件**：Data Object/Data Store/Text Annotation/Group
- 内建状态持久化/集群/重试/水平扩展

**层 2：bpmn-bridge 同源中介 + 适配层（process-svc 内）⭐**
- `flowgram-to-bpmn`：flowgram 节点图 JSON → BPMN 2.0 XML
- `bpmn-to-flowgram`：BPMN XML → flowgram 节点图 JSON，子集外元素转只读占位
- `capability-check`：解析 XML 判定可编辑/只读
- **Camunda Job Workers**：对象操作/连接器/通知/表达式 Worker
- **流程上下文桥接**：流程变量 ↔ aPaaS 对象/视图模型双向同步

**层 3：双模式可视化建模器（前端）⭐**
- **标准模式（bpmn-js）**：完整 BPMN 2.0 建模器，全元素调色板+属性面板+XML 导入导出+协作图泳道
- **简化模式（Fork flowgram.ai 深度定制）**：保留双布局(Fixed/Free)、节点配置表单、变量作用域链、物料体系、性能优化(Web Worker/增量渲染/缓存)；Fork 定制点：① 物料替换为 aPaaS 业务节点对接对象字段 ② 运行时改为产出 BPMN XML(同源) ③ 接入 capability-check 只读锁定+占位提示
- **模式切换**：一键切换不丢数据；只读流程提示切回标准模式

### 模块 4：权限与多租户

- **多租户**：`tenant_id` 行级隔离 + PostgreSQL RLS 兜底
- **RBAC + 五级权限**：页面/记录(行级条件)/流程(触发/审批/任务分配)/数据模型(对象+字段级)/连接器
- **用户/角色/组织**：用户表、角色表、用户-角色、树形组织架构
- **流程权限**：对接 Camunda Tasklist 任务分配与候选组，映射 aPaaS 角色
