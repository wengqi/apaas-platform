# 修复"不包含→表达式→可视化"切回时 r.join 错误

## 根因

- `loadFromJsonLogic` 内部有 try-catch，能捕获 RAQB 同步错误并返回 emptyTree
- 但 React 渲染阶段 RAQB 组件内部对 tree 调用 `.join()` 时同步抛错，绕过 try-catch
- 错误信息 `r.join is not a function` 表明 RAQB 期望字符串数组但实际收到其他类型（可能是 Immutable List 或 Map）
- 表达式模式 `jsonLogicToExpression` 转换时对某些 RAQB 树结构调用 join

## 修复策略

### 1. ConditionConfigForm.tsx - ConditionEditor 增强稳定性

`handleTabChange('visual')` 当前直接 setTree(loadFromJsonLogic(...))，错误冒泡到 React 渲染层。改为：

- 缓存成功加载的 tree 副本
- 捕获渲染异常（如通过 React 组件错误处理）
- 当 `condition` 包含 `not_contains`/`in`/`notIn`/`isEmpty` 等函数类操作符时，先验证 RAQB 能 round-trip，否则降级到 `exportToJsonLogic(exportToJsonLogic(loadFromJsonLogic(condition))` 形式

### 2. ConditionConfigForm 层级错误边界

在 ConditionEditor 外面包一层 React ErrorBoundary，捕获组件渲染阶段的异常并降级显示

### 3. 修改 normalizeJsonLogic 增强覆盖

当前 normalizeJsonLogic 仅处理 `and`/`or` 单对象情况。增加：
- `{"!": {"in": [...]}}` 中 in 参数顺序的规范化
- `isEmpty` 格式: `{"!": {"var": "x"}}` → RAQB 期望的特定结构

### 4. 增加精确 round-trip 测试

不再用 generic variables，每个操作符测试用专属变量（tags/status/remark）确保字段存在

## 测试验证

- typecheck + lint + test
- 完整 Docker 重建部署
- 浏览器验证：不包含→表达式→可视化 不再报错
- 其他操作符回归测试
