# 修复"不包含→表达式→可视化"往返时 r.join 报错

## 根因
用户在 ElseIDFix 流程中：选择"不包含"操作符 → 切换到表达式模式（jsonLogicToExpression 输出 `notContains(tags, "vip")`）→ 切回可视化模式（expressionToJsonLogic 输出 `{"!": {"in": ["vip", {"var": "tags"}]}}`）→ RAQB `loadFromJsonLogic` 抛 `r.join is not a function`。

之前修复了 `and`/`or` 单对象包装场景，但没覆盖 RAQB 加载端对 `{"!": {"in": ...}}` 格式的特定要求。

## 修复策略

### 1. 在 normalizeJsonLogic 中补强
- 检测 `{"!": {"in": [val, {var: field}]}}` 格式（contains/notContains）→ 改为 RAQB 期望的格式
- 或更通用的方式：在 expressionToJsonLogic 输出后、loadFromJsonLogic 加载前进行格式归一化

### 2. 测试覆盖
为 6 个核心操作符添加 round-trip 测试：
- `== != > < >= <=`
- `contains / notContains`
- `in / notIn`
- `isEmpty / isNotEmpty`

测试流程：`expressionToJsonLogic(text) → loadFromJsonLogic(json) → exportToJsonLogic(tree) → 验证格式一致不报错`

### 3. 验证
typecheck + lint + test + build + deploy
