# ADR-0002: 平台定位修订 — 企业内部真实使用，目标环境为非飞书的企业环境

- 状态：已接受
- 日期：2026-09-27
- 关联：`docs/research/RESEARCH-feishu-apaas-live-benchmark-2026-09-27.md`（实地对标调研）、`docs/roadmap/ROADMAP.md`（2026-09-27 重规划节）

## 背景

1. 原「总体目标」为复刻飞书 aPaaS 完整功能体系（已排除 AI 模块与飞书生态集成），AGENTS.md「飞书 aPaaS 对齐原则」将飞书功能作为全面对标基准，但**未区分「平台能力形态」与「飞书生态特有能力」**，也未明确平台自身服务的对象与环境。
2. 2026-09-27 实机对标调研（36 项能力矩阵：对齐 7 / 部分 15 / 缺失 14，实测口径对齐度约 53%）表明：若全面补齐，工作量远超单人项目承载，必须收缩范围。
3. 同日与需求方确认四项定位答案：**企业内部真实使用**；使用者**先开发者后业务**；目标环境**非飞书**（其他企业环境，如企业现有 SSO/4A/目录体系）；行动顺序**先收尾（合并 PR #1 整改）再重规划**。

## 决策

1. **定位**：面向企业内部真实使用的低代码平台。首要成功标准 = 能用平台**完整交付并运行一个真实业务应用**（表单 + 审批 + 报表类），而非对齐度数字。
2. **目标环境**：非飞书 aPaaS 的企业环境。组织与身份通过**可插拔对接层**接入（协议候选：OIDC / SAML / CAS 做 SSO，LDAP / SCIM / 定时同步做组织目录），具体企业适配器按首个落地环境确定（待需求方确认，见"开放问题"）。
3. **使用者**：先开发者后业务。当前阶段所有交互按开发者效率优化；AI 生成页面/流程、低门槛化改造降为远期项。
4. **对标口径修订**：飞书 aPaaS 仅作为**平台能力形态参考**（版本模型、权限语义、流程触发/节点语义、观测分类、编辑器信息架构）；以下飞书生态特有项**移出对标范围**，不再视为缺口：官方连接器市场、飞书审批/飞书事件、AI 专区与 AI 实践模板、MCP Server、方案中心行业模板。
5. **流程与审批**：自研流程引擎与审批节点保留（不改为对接外部审批中心），但需补齐真实审批语义：流程表单绑定、审批人分环境配置、会签/或签/依次审批、审批结果变量。
6. ROADMAP 新优先级以「2026-09-27 重规划」节为准（P0：身份与组织对接层、草稿→提交版本模型、流程表单与审批语义、运行环境多环境化；P1：观测分类、流程效率分析、权限查询、全局选项；暂缓：AI 生成、模板市场、MCP、移动端、多语言）。

## 后果

- 正面：范围聚焦到单人可执行；验收标准从"对齐度"变为"可交付真实应用"；飞书生态类缺口不再产生技术债焦虑。
- 负面/代价：
  - 放弃飞书生态集成红利（消息/审批中心/连接器市场），企业内消息通知、待办入口需要自建或经目标环境适配层实现。
  - **身份与组织对接层是新增前置工程**（此前只有 JWT + 种子用户），在它完成前平台不具备真实企业可用性。
- 开放问题（需求方确认后关闭）：首个落地环境的具体身份协议（OIDC/SAML/CAS）与目录源（LDAP/SCIM/CSV 同步）、是否需要适配企业微信/飞连作为登录入口。
