## 一、产品定位与核心理念

### 定位
飞书 aPaaS 定位为「新一代企业智能系统开发平台」，核心理念「**要低代码，不要低能力**」。不是简单的拖拽生成页面工具，而是完整的低代码工具箱，让用户无需编写复杂代码就能搭建管理数据和跑流程的业务系统。

### 五大核心功能支柱
1. **页面展示** — 创建用户操作界面（表单、看板、卡片等）
2. **数据维护** — 建立数据表，管理业务数据
3. **流程创建** — 搭建自动化审批、通知和任务流转的业务流程
4. **集成连接** — 连接飞书内外系统
5. **应用权限** — 精确控制不同员工对数据和功能的访问权限

### 规格指标
| 维度 | 飞书规格 |
|------|----------|
| 单对象数据容量 | 2000 万行 |
| 单应用对象数 | 2000+ |
| 页面组件数 | 130+ |
| 流程节点数 | 150+ |
| 单应用流程数 | 700 |
| API 集成 | 2000+ |

### 架构哲学 — 模型驱动、低代码
| 层 | 职责 |
|---|---|
| 数据层 | 对象（直接创建的实体）+ 数据集（数据流加工后的物化数据） |
| 逻辑层 | 流程引擎（触发器/分支/持久化/代码节点）+ 事件系统（JS 扩展） |
| 表现层 | 拖拽式页面搭建器，PC/移动端同步，图表 + 自定义组件 |
| 集成层 | 飞书组织架构/消息/应用生态 + OpenAPI 凭证管理 |
| 治理层 | 多粒度 RBAC + 环境隔离 + 运营报表 |

## 二、完整功能模块清单（11 大模块 A-K）

### A. 对象与数据建模

#### A.1 对象管理
- 创建/编辑/删除（删除前校验：存在记录/被关联/被引用时阻止）
- 对象列表（搜索/排序）+ 对象详情（主从布局）
- 复制对象结构（不复制数据）
- 导出对象定义 JSON（跨环境迁移）
- 图标库、主显示字段、系统对象标记

#### A.2 字段类型（20+ 种）

| 分类 | 类型 | 配置项 |
|------|------|--------|
| 文本类 | 单行文本、多行文本、富文本、自动编号 | 最大长度、编号规则格式 |
| 数值类 | 数字、金额、百分比 | 小数位数、货币代码 |
| 选择类 | 单选、多选、复选框 | 选项列表(id/label/color/isDefault) |
| 日期类 | 日期、日期时间 | 显示格式 |
| 媒体引用类 | 附件、人员 | 最大数量、是否多选 |
| 关联计算类 | Lookup、子表(SubForm)、公式(Formula)、汇总(Rollup) | 目标对象、关系类型、表达式、聚合方式 |

#### A.3 字段属性
必填、唯一、可搜索、默认值（字面量或表达式）、描述、API名称(snake_case, 创建后不可改)、显示名称、字段级加密

#### A.4 关联关系
- 一对多（Lookup 在「多」方添加）、反向关联字段（自动生成）
- 多对多（通过中间对象）、级联删除、主子表
- 关联记录选择器（录入时弹出目标对象列表视图供选择）

#### A.5 视图（6 种）
| 视图 | 描述 |
|------|------|
| 列表视图 | 表格形式：字段显隐拖拽、筛选(嵌套AND/OR)、多字段排序、分页、分组、快速搜索、内联编辑、默认视图 |
| 详情视图 | 单条记录只读展示布局 |
| 表单视图 | 新增/编辑记录的表单布局 |
| 看板视图 | 按单选字段分组的卡片看板 |
| 日历视图 | 按日期字段排布 |
| 画廊视图 | 附件为主的卡片画廊 |

**筛选操作符（15 种）**：eq / ne / contains / not_contains / starts_with / ends_with / gt / gte / lt / lte / is_empty / is_not_empty / in / not_in / relative_date

#### A.6 系统字段
id / name / created_at / updated_at / created_by / updated_by

### B. 数据集与数据流（飞书核心亮点之一）

#### B.1 数据集
- 是**实体数据**（物化结果），非视图
- 必须通过数据流加工生成，不能直接创建
- 与对象的区别：对象可直接 CRUD，数据集需数据流加工

#### B.2 数据流设计
- 多表 join 关联
- 分组汇总（group by + aggregate）
- 数据筛选
- 输出到数据集
- 全局共享选项参数

### D. 流程引擎（飞书核心亮点之一）

#### D.1 触发器（5 种）
| 触发类型 | 描述 |
|----------|------|
| 记录事件触发 | RECORD_CREATED / RECORD_UPDATED / RECORD_DELETED |
| 定时触发 | Cron 表达式定时调度 |
| 手动触发 | 用户在 UI 手动启动 |
| 按钮点击触发 | 页面按钮 onClick 触发 |
| API 触发 | 外部系统通过 API 调用触发 |

#### D.2 流程节点（150+ 种，5 大类）

| 类别 | 节点类型 |
|------|----------|
| 触发与起止 | 触发器、开始、结束 |
| 数据操作 | 数据持久化、对象操作(CRUD)、批量操作 |
| 流程控制 | 逻辑分支(条件)、并行分支、包容分支、循环、延时、等待条件、子流程调用、跳出循环、继续循环 |
| 业务操作 | 人工任务审批、发送通知、HTTP请求、代码处理、赋值设置变量 |
| 注释 | 注释节点 |

#### D.3 变量系统 — 四态值类型（IFlowValue）
| 类型 | 描述 |
|------|------|
| constant | 直接常量值 |
| ref | 引用流程变量路径（如 `trigger_0.output.recordId`） |
| expression | 表达式求值（如 `amount > 1000`） |
| template | 模板插值（如 `订单 {{trigger_0.output.orderNo}} 已通过`） |

#### D.4 流程运行时
- 流程实例 + 节点执行状态追踪
- 流程变量作用域
- 异步执行（BullMQ 队列）
- 重试机制 + 状态持久化 + 崩溃恢复
- 流程监控仪表盘

#### D.5 流程模板
- 预置 20+ 业务场景模板
- 自定义编排

### E. 权限与多租户

#### E.1 五级权限体系
| 权限维度 | 描述 |
|----------|------|
| 页面权限 | 控制页面可见性 |
| 记录权限（行级） | 基于条件表达式控制记录可见性 |
| 流程权限 | 控制流程启动/审批权限 |
| 数据模型权限 | 对象 + 字段级（列级） |
| 函数权限 | 连接器/云函数调用权限 |

#### E.2 权限粒度
- 表级（对象级）
- 列级（字段级白名单 fieldScope）
- 行级（条件表达式 condition → 翻译为 WHERE 子句）
- 人员级

#### E.3 角色与组织
- 角色：应用级（appId 非空）+ 租户级（appId 为空）
- 内置角色（不可删除）
- 组织架构同步 + 组织授权（角色授权给组织节点 → 成员自动获得角色）
- 权限扩散（组织节点下所有成员继承角色）

#### E.4 多租户
- 租户隔离（tenant_id 行级隔离）
- 应用级隔离
- 字段级加密
- 行级安全（PostgreSQL RLS）
- 行为追踪（审计日志）

### I. 应用管理

#### I.1 应用生命周期
- 创建 → 编辑 → 发布 → 版本管理 → 归档
- 应用快照（含对象+页面+流程+权限完整副本）

#### I.2 环境管理
- 开发环境（develop lane，可实时编辑）
- 沙箱环境（sandbox）
- 生产环境（production，已发布不可变版本快照，可回滚）
- **核心原则：开发态修改不直接生效到运行态，必须经检查→发布**

#### I.3 应用创建流程
1. 两个入口：首页 Portal（5 种创建方式）+ 开发中心
2. 模板选择：全屏对话框，60+ 模板，三大筛选维度（应用类型/业务场景/行业）
3. 空白创建表单：图标 + 名称(中英双语) + 描述 + 命名空间(自动生成 `package_xxxxxx__c`)
4. 异步安装过程：进度条（40%→70%→100%），支持后台运行
5. 创建后预置：系统对象(User/Department)、预置角色、记录权限规则

#### I.4 应用发布流程
1. **发布前置检查**：异步检查（30%→80%→100%），覆盖页面/数据模型/流程/权限/云函数
2. **查看变更**：按模块分类展示变更项（云函数/记录权限/角色），含变更类型/变更人/变更时间
3. **发布向导**：版本号(语义化，预填 0.1.0，自动递增) + 更新说明(500 字符) + 变更内容自动生成
4. **发布历史**：版本列表表格 + 回滚
5. **发布后状态**：待发布→已发布、访问/分享按钮 enabled

#### I.5 应用管理后台
- 基础信息：概览(运营报表) + 环境信息 + 发布历史
- 业务管理：应用权限 + 数据管理 + 审批管理 + **审计日志**
- 运维监控：运营报表 + 应用观测 + 监控设置
- 开放能力：MCP 服务 + Open API + 数据共享

## 三、平台业务流与交互

### 3.1 整体业务流
```
登录 → 首页 Portal → 开发中心 → 应用构建器（7 大模块）
  → 检查 → 发布 → 上架 → 应用管理后台
  → 流程中心（任务/效率分析）→ 应用中心
```

### 3.2 开发态 vs 运行态分离（核心设计原则）
| 维度 | 开发态 | 运行态 |
|------|--------|--------|
| 域名 | dev 独立域名 | prod 独立域名 |
| 用户角色 | 搭建者 | 终端用户 |
| 数据环境 | 隔离 | 隔离 |
| 版本 | 可实时编辑 | 已发布不可变快照 |
| 页面来源 | 实时编辑 schema | 已发布快照 |

### 3.3 构建器布局
- **三栏布局**：左资源管理器 + 组件面板 / 中画布 / 右属性面板
- **底栏**：错误检查 / 控制台 / 请求时间轴 / 性能
- **7 大模块图标导航**：页面 / 数据 / 流程 / 云函数 / 权限 / 观测 / 集成

### 3.4 关键交互模式
- 异步操作 + 进度反馈（创建应用、检查、发布均为异步）
- 变更追踪（Change Tracking）
- 预检机制（Pre-publish Check）
- 版本管理（语义化版本号 + 回滚）
- 模板驱动（应用 60+ / 页面 14+ / 流程 20+ / 对象 6 种创建方式）
- 双端自适应（PC 端设计自动同步移动端）

## 五、对齐开发规则

1. **功能开发前**：查阅本文档对应模块，确认飞书实现方案
2. **PRD 编写时**：以飞书功能为基准，标注「对齐/增强/简化/偏离」
3. **UI 设计时**：参考飞书交互模式（三栏布局、异步进度、模板驱动等）
4. **偏离时**：在 PR/commit 中说明偏离理由（如"独立平台不依赖飞书生态"）
5. **本文档更新**：每次 Phase 完成后更新对齐度矩阵
