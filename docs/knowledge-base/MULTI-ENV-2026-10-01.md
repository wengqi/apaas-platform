# R1.4 多环境实现记录（2026-10-01）

> 设计稿：`docs/design/DESIGN-identity-env-versioning-2026-09-27.md` §3.2/3.3/3.7；ROADMAP R1.4 = M2+M3（M4 hotfix 流不在本轮）。
> 核心原则：**构建态一套（值与配置分离）；环境差异全部收敛到「环境变量值 + 环境指针」；版本快照不可变，发布只是切指针。**

## 1. 数据模型

| 模型 | 说明 |
|---|---|
| `AppEnvironment` | dev/prod 环境行，`currentVersionId` 指针；@@unique([appId, key]) |
| `Deployment` | 发布/回滚历史（kind=deploy\|rollback + operator + note） |
| `EnvVarDef` / `EnvVarValue` | 应用环境变量：构建态一套定义 + 按环境设值；敏感值 AES-256-GCM（复用 CONNECTOR_ENCRYPTION_KEY） |
| 运行数据 | `records` / `process_instances` / `node_executions` / `auto_number_counters` 加 `environmentId`（默认 prod backfill）；AutoNumber 序列 dev/prod 独立（唯一键扩为 [objectId, prefix, environmentId]） |
| `ProcessInstance.frozenWorkflowSchema` | 实例启动时冻结流程 schema（运行态不变量 3：版本切换不影响在途实例） |

迁移 `20261001093000_add_multi_environment`（不可回改），含存量应用 dev/prod 环境行 backfill（`env_dev_<md5>` 确定性 id）。

## 2. 双维注入（packages/db）

`TenantStore` 增加 `environmentId`；`runWithEnv(tenantId, env, fn)`；`ENV_SCOPED_MODELS` 白名单（Record/ProcessInstance/NodeExecution/AutoNumberCounter）。**环境上下文为空 → 不注入不告警**（与租户 fail-open 不同：兼容无环境概念的既有路径）。raw SQL 旁路（record 查询下推）显式拼 `environment_id`。

## 3. 环境解析与读路径

- **EnvironmentResolverService**（environment-core.module，独立文件防模块循环导入）：指针→AppVersion.snapshot → 降级 `Application.publishedSnapshot` → null（活表）。**缓存只存原始快照**，`${env.*}` 在每次读取时实时替换（环境变量改值立即生效，无需失效）；发布/回滚 `invalidateApp`。
- 环境上下文入口：`TenantContextInterceptor` 解析 `?env=` / `X-Env`（白名单 dev|prod，缺省 prod——与现状等价）。
- 读路径切换：页面 slug（bundle）/ 审批页渲染（新端点 `GET /apps/:id/pages/runtime/:pageId`，实例环境优先）/ 对象字段（record create/update/list + chart-data）/ 流程引擎（bundle 内流程=已发布语义；executeNextNode 优先 frozenWorkflowSchema；节点执行 runWithEnv 实例环境）。
- **兼容不变量**：无指针的应用（seed/存量）永远走旧路径，行为零变化——全量旧 e2e 零改动通过。

## 4. 发布与触发器

- `POST /apps/:id/publish` = 提交版本 + 部署 prod（挂指针 + Deployment）；发布向导可选"仅 dev"。
- `POST /apps/:id/environments/:envKey/publish|rollback`、`GET .../environments`、`GET .../environments/:env/deployments`、`POST .../preflight`。
- **G4 预检**：目标环境必填 EnvVarValue 缺失 → 400 硬拦；破坏性变更（changeSet DELETE）与 `${env.*}` 引用清单（G1 第一版）为警告级。
- **触发器随环境启停**：BullMQ jobId 扩为 `scheduled:<envKey>:<processDefId>`（job data 携带 envKey），清理按 jobId 精确匹配——顺带修复旧实现仅按 cron pattern 清理导致同 cron 流程互踩的 bug；`rebuildForEnvironment` 按 bundle 重建（bundle 无 cron 回退活表）；`onRecordEvent` 按记录环境只触发同环境流程。

## 5. 前端

- studio「环境管理」页：dev/prod 指针卡片 + 版本部署/回滚 + Deployment 历史 + 环境变量（定义一套，dev/prod 各自设值；敏感值"已配置（不可读）"）；PublishWizard 目标环境选择。
- runtime-ui 顶栏环境切换（`?env=`）；PageView 与审批页按环境 bundle 渲染。

## 6. 踩坑记录

1. **EnvironmentModule ↔ ProcessModule 文件级循环导入**（Nest 报 "module at index [1] is undefined"）：EnvironmentCoreModule 必须独立成 `environment-core.module.ts` 文件。
2. **resolver 缓存替换后 bundle 会让环境变量改值失效**：缓存必须存 raw 快照，替换放读取时。
3. **`prisma migrate dev` 非交互 shell 因唯一键变更警告被拦**：沿用 `migrate diff --from-url --to-schema-datamodel` 手工生成迁移 + 追加 backfill SQL。
4. **e2e 版本选择用 `versions[0]` 依赖排序不可靠**：按 versionNumber 显式 find。
5. **测试断言需跟进行为参数**：onRecordEvent/autoNumber.generate 增加 env 参数后，`toHaveBeenCalledWith` 全量匹配的断言要补 `'prod'`。

## 7. 边界与已知缺口（本轮明确不做）

M4 hotfix 流（版本谱系）；连接器凭证按环境隔离（设计稿开放问题）；数据集物化行环境隔离；G1"仅值位置"机判硬校验（第一版警告级）；破坏性变更强制 UI 二次确认（当前 popconfirm 半自动）。
