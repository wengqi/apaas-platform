## 二、最重要的一个发现：UI 层系统性契约断链

**真实用户从浏览器执行的核心路径，在评审起点上有 4 条是 100% 失败的，而 CI E2E 全绿。**

原因：现有 10 个 Playwright spec 全部"通过 API 调用操作，配合 UI 验证"（02-object-crud.spec.ts 注释自述），UI 层的前后端契约分歧从未被真实点击暴露。

四个同模式缺陷（前端多发字段/错字段名，后端 ValidationPipe `forbidNonWhitelisted` 400）：

| # | 用户操作 | 失败原因 | 后果 |
|---|---|---|---|
| BUG-01 | 新建对象/改名 | 前端发 `label`，后端只认 `name` | 对象建模 100% 失败 |
| BUG-04 | 新建视图 | 多发 `isDefault` | 视图创建 100% 失败 |
| BUG-08 | 保存页面 | 多发 `apiName/type/objectId` | 搭建器保存 100% 失败（画布内容无法持久化） |
| BUG-03 | 创建/更新记录 | 多包一层 `{data}` | JSONB 双层嵌套 `data.data`，列表读不到值 |

另有 BUG-02（记录表单 `FieldControl` 未接收 Form.Item 注入的 value/onChange，全部控件非受控）使**新增/编辑记录对任何字段类型都必然校验失败**——与 BUG-03 叠加意味着"记录管理"在 UI 上完全不可用。

> 全部已在本次修复（commit dda52c4），并在浏览器中回归验证。

## 三、已修复并回归验证（commit dda52c4）

1. **BUG-01 (P0)** 对象创建/改名 400 — `ObjectListPanel/ObjectDetail/api/objects.ts` label→name。
2. **BUG-02 (P0)** 记录表单全字段非受控 — `RecordFormDrawer.FieldControl` 接收并透传 value/onChange，覆盖全部 14 种字段控件。
3. **BUG-03 (P1)** 记录 JSONB 双层嵌套 — `api/objects.ts` create/update 去掉 `{data}` 包装，对齐后端契约（ApiBody 文档与 e2e 用法均为裸键值对）。
4. **BUG-04 (P1)** 视图创建 400 — `isDefault` 并入 `config` JSON 存取，API 层映射回顶层保持 UI 语义。
5. **BUG-08 (P0)** 页面保存 400 — `BuilderToolbar` 保存/发布 payload 收窄为 `{name, schema}`。
6. **数据绑定入口缺失** — `DataBindingTab` 为 data_table/list/chart/detail_card 注入 `data`/`record` 绑定 key（此前用户无任何 UI 途径把视图模型变量接到数据组件）。
7. **BUG-06 (P1) + 安全 H-1** — gateway user list/get/create 返回原始实体泄漏 `passwordHash`，且 `userRoles` 未拍平致前端角色列全"无"；补 `toDto()`（白名单 + roles 拍平）。
8. **BUG-09 (P1) 审计盲区** — `TENANT_ADMIN` 被 `isSuperAdmin` 短路放行并**跳过审计写入**，权限最高的角色操作零审计；短路分支补 `ALLOWED_SUPERADMIN` 审计（已验证入库）。
9. **审计注入缺失无告警** — `PermissionGuard` 的 `@Optional` 注入静默降级；缺失时告警一次。

## 四、重大缺陷与功能缺失（未修复，留待决策）

### A. 流程执行链在 UI 层断裂（P1 功能缺失）
- 手动触发（MANUAL）流程**没有任何 UI 启动入口**（列表 more 菜单只有导出/删除；后端 `POST /processes/:id/start` 无 UI 消费方）。
- 触发器类型"创建后再配置"，但流程编辑器**无触发器配置界面**（`ProcessEditor.tsx` 全文无 trigger 编辑 UI）。
- 结果：用户在 UI 上无法走通"配触发器→发布→自动执行"，只能依赖种子数据预置。

### B. 流程配置侧栏刷新后交互冻结（P1，稳定复现）
- 打开节点配置面板后刷新/恢复页面：侧栏内所有 AntD Select 无法展开、Input 无法键入、关闭按钮失效，且侧栏遮挡顶部工具栏按钮。已排除禁用态/遮挡/事件未达——事件到达但 React 更新链路不生效（疑似订阅/实例断链）。**当前会话（首次打开）交互正常**，故流程设计-发布链路本次仍验证通过。

### C. 单选字段值约定分裂（P1 数据一致性）
- UI 单选字段以**中文 label 为 value** 存储（"待审批"），种子数据/流程条件用英文枚举（PENDING/APPROVED）。
- 实测后果：审批通过后，流程条件分支 `status=='APPROVED'` 永不匹配 → 「更新资产状态」「通知申请人」下游节点**全部不执行**。审批任务完成但业务数据未流转，且通知中心无任何消息。

### D. E2E 测试战略缺陷（P1 质量）
- 10 个 spec 全部 API 直调 + UI 只做断言，导致上述 UI 全断链 CI 全绿。需要补充真实 UI 交互层 e2e（尤其表单提交/保存类路径）。

### E. 后端架构 P0×2（见后端评审 6.5/10）
- `batch-operation.executor.ts:78` 批量更新整列覆盖 JSONB `data`，静默丢全部其他字段。
- `process-engine.ts:73` 实例锁是进程内 Map，多副本部署必丢令牌（实例永久卡 RUNNING）。
- P1 还有：已发布流程可原地改 Schema、TERMINATED 实例可被审批复活、数据集 REFRESHING 无租约永久卡死、多角色 ALLOW 规则取"第一条命中"不确定、流程节点写库绕过校验/触发器、BullMQ 无重试/死信/巡检、应用发布不注册定时触发器且会把 DRAFT 流程一并发布。

### F. 安全 Critical（见安全评审 5.5/10）
- **默认凭证链**：生产 compose 内置 `JWT_SECRET` 弱默认值 + `CONNECTOR_ENCRYPTION_KEY` 全零默认 + entrypoint 每次启动跑 seed（明文 superadmin123/admin123）+ 登录页展示测试账号。三选一即可打穿。
- High：登录防爆破失效（auth 限流桶定义未绑定）；HTTP 连接器 baseUrl/tokenUrl 出站 SSRF（可读回显，可打 169.254.169.254/内网）；租户 SUSPENDED 后存量 JWT 仍有效最长 7 天。（passwordHash 泄漏已随本次修复）
- Medium：流程实例变量同租户可读（实例级授权缺失）；run_script 主窗 `new Function` + token 存 localStorage 组合横向移动链；云函数 PUBLISHED 后代码可静默替换；webhook 无签名/防重放且 token 进访问日志；Swagger 生产无条件暴露；生产 compose 发布 PG/Redis 端口且 Redis 无密码；云函数 Isolate 无全局并发预算（50 并发 = OOM）。

### G. 数据层（重点两项）
- `records.data` 的 GIN 索引（jsonb_ops）与实际查询算子（`->`/`->>`/LIKE）**不匹配**，等于无索引收益；业务字段排序回退为整列 JSONB 序（语义错误）。
- 可空列上的复合唯一约束失效（`OrgRoleGrant(orgId,roleId,appId NULL)`、平台超管同邮箱可重复）。

### H. 产品/UX 缺陷清单（P2 级）
- 记录表单暴露系统字段（创建人/创建时间/审批状态等可手填，创建人后端虽强制注入但 UI 误导）。
- 记录列表系统字段列重复渲染两遍；创建人列显示原始用户 ID 而非姓名。
- 审批任务详情把 record 显示为原始 JSON，未渲染业务表单。
- 流程节点副标题显示原始枚举（SINGLE）；配置完整仍显示"有未完成的配置"。
- 发布人显示用户 ID 而非姓名。
- runtime-ui 首页可见 DRAFT 应用（含"开发中"应用）。
- 流程编辑器"打开即脏"（未保存标记在刚打开已保存流程时即出现，撤销栈被污染）。
- 页面搭建器无脏跟踪 + 加载失败静默回退空 Schema（后者是数据覆盖事故路径）。
- React Query key 注册表为死代码、别名 key 漏失效；19 个文件超 400 行规范上限；登录页展示明文测试账号。

### I. 文档准确性
- AGENTS.md "Phase 0-10 全部完成，ROADMAP 无未实现项"为过度声明：ROADMAP 自身仍有 3 个 ⚠️ 项（自定义组件注册/环境隔离/应用级审计 UI），且本次实测新增多处文档未载断链。

- 页面搭建器：组件库、拖拽放置、属性面板（基础/样式/数据绑定/事件）、撤销栈、视图模型变量定义、保存（修复后）
- 流程：创建、flowgram 画布（节点增删/校验标记）、人工任务配置（审批人类型 5 种/审批模式/表单/截止/驳回/抄送）、发布、版本生成、发布历史

## 六、综合评分与结论

| 维度 | 评分 | 一句话 |
|---|---|---|
| 后端架构 | 6.5/10 | 租户隔离纵深扎实；引擎并发/恢复语义停留在单进程，双写路径分裂，队列零治理 |
| 前端架构 | 7/10 | 类型安全/事件驱动/消毒到位；脏状态完整性、数据覆盖路径、Query key 治理扣分 |
| 数据层 | 6/10 | 模型纪律好；JSONB 索引错配与唯一约束失效是硬伤 |
| 安全 | 5.5/10 | 内功 7-8 分水准；默认凭证链+SSRF+防爆破失效拉低，不可直接上线 |
| **生产就绪度（综合）** | **约 60%** | 适合单副本预生产演示；不具备多副本、审计完整性与安全上线条件 |

**核心矛盾**：工程基建（类型契约、隔离、文档纪律）明显高于平均，但"用户真实操作路径"的质量保障完全缺位——UI 四条主路全断而 CI 全绿是最直接证据。

## 七、建议的整改优先级（供决策）

1. **立即**（已由本次修复覆盖大半）：补真实 UI 层 E2E（表单提交/保存/发布路径）；密码哈希泄漏已修。
2. **上线前必须**：安全 C-1 默认凭证链、H-2 防爆破、H-3 SSRF、H-4 租户挂起；审计盲区已修但需补"业务动作级"审计（现在只有 PERMISSION_CHECK）。
3. **下一个迭代**：流程 UI 断链（手动启动入口 + 触发器配置界面）、单选字段值约定统一、流程侧栏冻结、批量更新整列覆盖、Redis 分布式锁。
4. **持续**：React Query key 治理、400 行拆分、GIN 索引策略、队列重试/死信/巡检。
