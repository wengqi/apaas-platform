# 测试旅程地图 — 核心用例保整体正确（活文档）

> 创建：2026-10-06。回答的问题："模块很多且互相关联，改一处后，跑哪些用例能确信整体流程没坏？"
> 定位：**冒烟旅程保脊柱，单测保器官，全量 e2e 在 CI 兜底**——三层各司其职。

## 一、七条核心旅程（平台脊柱）

| # | 旅程（用户故事一句话） | 覆盖 spec | 串联模块 |
|---|---|---|---|
| J1 | 我能登录，租户之间互相看不见 | e2e/01-auth | auth、租户隔离 |
| J2 | 我能建模对象、增删改查记录 | e2e/02-object-crud | object、record（JSONB 宽表） |
| J3 | 提交→触发→审批（会签/或签/依次）→批准归档 | e2e/16-procurement-approval | record 触发、流程引擎、user_task 聚合 |
| J4 | 驳回→状态回写→申请人收到通知→台账可见 | e2e/22-feedback-loop | 引擎 writeback、通知、runtime-ui 台账 |
| J5 | 界面标签不说谎（已发布≠未保存、配置完整≠标红） | e2e/23-ui-truthfulness | studio 编辑器、发布向导 |
| J6 | AI 草稿→人审→批准落地（治理链） | e2e/17-review-center | review、版本模型、@ref 令牌 |
| J7 | 外部系统持 API Key 经 /open/* 触发流程 | e2e/19-open-api | open-api、X-API-Key、引擎 |

**冒烟套件 = J1+J2+J3+J4+J5**（`pnpm test:e2e:smoke`，15 用例实测 ~16s）——覆盖"表单+审批+报表"平台的生存脊柱。J6/J7 为第二环（跨模块关节，CI 全量跑；改动治理/开放 API 时必须手动加跑）。

## 二、影响矩阵（改了 X → 必跑哪些）

| 改动的模块 | 必跑 | 说明 |
|---|---|---|
| auth / 租户 / 登录 | J1 + 冒烟全套 | 认证是所有旅程的前置 |
| object / record（含字段、校验、Formula/Rollup） | J2、J3、J4 | 记录是主链路的血液 |
| 流程引擎（执行器/completeTask/聚合） | J3、J4（+J7 若涉触发入口） | 多模式审批与回写都在这 |
| writeback / 通知 / runtime-ui | J4 | 反馈环三断言 |
| review / 版本模型 / 发布 / 环境 | J5、J6（+ e2e/09、18 全量） | 治理链与环境指针 |
| dataset / chart-data | e2e/07-dataset | 报表腿 |
| open-api / API Key | J7 | headless 形态 |
| studio 编辑器（画布/序列化/面板） | J5 + **GUI 黑盒走查**（见 AGENTS.md QA 走查约定） | 标签说谎类缺陷聚集地 |
| MCP / 方言指南 / 校验器 | J6 + 对应校验器单测 | AI 生成入口 |

## 三、三层分工与边界（诚实说明）

- **单测**（gateway 746 等）：器官级正确性，秒级，改哪跑哪；
- **冒烟 e2e**（本图 J1-J5，16s）：推送前确认**脊柱未断**——它回答"系统还能用吗"，不回答"每个功能都对吗"；
- **全量 e2e**（CI，23 个 spec）：器官间关节全覆盖，PR 合并前兜底。

冒烟保不了的东西（不要对它过度期待）：视觉审美、业务规则正确性（只有业务方知道）、未写断言的新缺陷类别。新缺陷类别出现时（如本轮"标签说谎"），**先转成不变量断言再修**，让回归防护网随缺陷进化。

## 四、运行命令

```bash
pnpm test:e2e:smoke   # 推送前/改动后快速确认脊柱（~16s，需本地服务在跑）
pnpm test:e2e         # 全量（CI 强制）
```
