## 一、应用创建全流程

### 1.1 创建入口

应用创建有**两个入口**：

1. **首页 Portal** (`/ae/portal`) → 「快速新建应用」区域，提供 5 种创建方式卡片：
   - 从空白开始新建
   - 新建 BPM 应用（业务流程管控轻松上手）
   - 新建门户工作台（多类型工作台供选择）
   - 新建机器人（自动化机器人快速创建）
   - 探索更多模板（业务 360、AI+ 等多种主题模板）

2. **开发中心** (`/ae/projects`) → 「新建应用」按钮

### 1.2 创建方式选择

点击「新建应用」后弹出**全屏模板选择对话框**，包含：

#### 顶部操作
- 搜索应用模板（文本搜索框）
- 「从导入新建」按钮（通过安装包链接导入已有应用）

#### 左侧筛选器（三大分类维度）

| 维度 | 选项 |
|------|------|
| **应用类型** | 门户工作台、BPM 应用、机器人应用 |
| **业务场景** | AI 实践、业务 360、IT/行政、销售/客户、项目管理、门店管理、人事管理、知识共享、常用工具、企业文化、流程审批 |
| **行业** | 制造、消费、通用、互联网、企业服务 |

#### 模板列表
60+ 应用模板卡片，每个卡片显示：
- 图标 + 名称
- 标签（应用类型 + 业务场景 + 行业）
- 安装次数
- 简介
- 提供方（如「北京飞书科技有限公司」）

#### 首选项
列表第一个是「从空白开始新建」— 最基础的创建方式，通过拖拉拽 + AI 辅助搭建页面。

### 1.3 空白应用创建表单

选择「从空白开始新建」后，弹出「新建空白应用」对话框：

| 字段 | 必填 | 说明 |
|------|------|------|
| **图标** | 否 | 可选择预设图标或上传自定义图标 |
| **名称** | 是 | 支持中英文双语输入（默认中文，可点击「添加英文」补充英文名） |
| **描述** | 否 | 应用用途描述，支持中英文双语 |
| **命名空间** | 是 | 自动生成格式 `package_xxxxxx__c`（如 `package_3faf34__c`），系统内唯一，可手动修改 |

#### 权益提示
表单顶部显示提示信息：
> 应用内可创建 5 个对象、20 条流程、20 个页面，可体验全部免费权益

并提供「查看权益对比」和「联系客服升级」链接。

### 1.4 异步安装过程

点击「创建」后，进入**异步安装流程**，显示进度条对话框：

```
正在安装 - 准备开发环境... (40%)
正在安装 - 同步创建飞书应用... (70%)
正在安装 - ... (100%)
```

**关键特性**：
- 支持「后台运行」— 用户可以关闭进度对话框，安装继续在后台进行
- 应用列表中实时显示安装进度（如「正在新建...40%」）
- 安装完成后，应用出现在列表中，状态为「待发布」
- 开发动态列显示「新建」
- 安装完成后自动打开应用构建器（新标签页）

### 1.5 创建完成后的初始状态

新应用直接进入**页面构建器**（Page Builder），初始状态：

**左侧面板**：
- 页面资源管理器（桌面端/移动端切换）
- 显示「请先创建页面或导航布局」

**中间画布**：
- AI 创建页面引导（输入需求描述，AI 生成页面）
- 快捷模板推荐（跟进记录填表表单、员工管理详情页、门店管理工作台等）
- 「自主搭建」区域（互动式教程引导）
- 页面模板选择器，按类型分类：
  - 数据列表、详情页、门户网站、仪表盘
- 14个页面模板可选：空白页面、企业内网、企业官网、工作台、品牌官网、任务工作台、卡片列表、基础列表、表格、详情页、用户主页、个人信息页、仪表盘(通用浅色/深色/风格化)等

**系统自动预置的内容**（在发布变更中可见）：
- 系统对象：用户 (_user)、部门 (_department)
- 预置角色：全部权限角色 (full_access_role)、全局只读角色 (global_reader_role)
- 记录权限规则：为系统对象自动创建的记录权限规则
- 云函数源代码：系统默认代码

## 二、应用发布全流程

### 2.1 发布前置检查（检查）

构建器顶部工具栏有「检查」按钮，用于发布前预检：

#### 检查流程
1. 点击「检查」→ 打开检查面板（右侧或底部滑出）
2. 面板显示「问题」标题和检查记录
3. 首次检查显示「没有检查记录」+「立即检查」按钮
4. 点击「立即检查」→ 开始异步检查，显示进度（30% → 80% → 100%）
5. 检查完成后显示结果：
   - ✅ 「暂无问题」— 可以继续发布
   - ❌ 显示问题列表，需修复后重新检查
6. 检查完成后显示「最近检查 {时间}」+「重新检查」按钮

#### 检查覆盖范围
检查覆盖所有模块的配置完整性：
- 页面配置（组件绑定、事件配置等）
- 数据模型（对象字段配置、关联关系等）
- 流程配置（节点配置、变量引用等）
- 权限配置（角色权限、记录权限等）
- 云函数（代码完整性等）

### 2.2 发布流程（发布）

#### 步骤 1：点击「发布」
- 顶部工具栏的「发布」按钮
- 弹出提示框（tooltip）：
  - 标题：「发布并上架到飞书工作台」
  - 操作1：「查看变更」— 查看本次发布的变更清单
  - 操作2：「去发布」— 直接进入发布向导

#### 步骤 2：查看变更内容（可选）
点击「查看变更」弹出「变更内容」对话框，按模块分类展示所有变更：

| 模块 | 变更项示例 | 变更类型 |
|------|-----------|----------|
| 云函数 | 源代码 | 更新 |
| 记录权限 | 「用户」对象的记录权限规则 | 新建 |
| 记录权限 | 「部门」对象的记录权限规则 | 新建 |
| 角色 | 全局只读角色 | 新建 |
| 角色 | 全部权限角色 | 新建 |

每个变更项显示：变更项名称、变更类型（新建/更新/删除）、变更人、变更内容描述

### 2.3 发布向导详细步骤

点击「去发布」进入「发布新版本」向导：

#### 向导布局
- 顶部：标题「发布新版本」+ 步骤指示器
- 左侧导航：版本信息 → 版本号 → 更新说明 → 变更内容 → （子项）云函数/记录权限/角色
- 右侧主区域：表单和变更详情
- 底部：「下一步」按钮

#### ① 版本信息区域

| 字段 | 必填 | 说明 |
|------|------|------|
| **版本号** | 是 | 预填 `0.1.0`，格式如 `1.2.1`（语义化版本），每次发布会自动递增 |
| **更新说明** | 是 | 文本输入，500字符限制，显示字符计数（如 `6/500`） |

#### ② 变更内容区域（自动生成）

按模块分类展示详细变更列表，每个模块一个表格：

**云函数变更表**：

| 名称 | 变更类型 | 变更人 | 最后变更时间 | 操作 |
|------|---------|--------|-------------|------|
| 源代码 | 更新 | 系统 | 2026-08-01 17:02 | -- |

**记录权限变更表**：

| 名称 | 变更类型 | 变更人 | 最后变更时间 | 操作 |
|------|---------|--------|-------------|------|
| 「用户」对象的规则 | 新建 | 系统 | 2026-08-01 17:02 | 查看详情 |
| 「部门」对象的规则 | 新建 | 系统 | 2026-08-01 17:02 | 查看详情 |

**角色变更表**：

| 名称 | 变更类型 | 变更人 | 最后变更时间 | 操作 |
|------|---------|--------|-------------|------|
| 全局只读角色 | 新建 | 系统 | 2026-08-01 17:02 | 查看详情 |
| 全部权限角色 | 新建 | 系统 | 2026-08-01 17:02 | 查看详情 |

#### ③ 下一步
- 必须填写版本号和更新说明后，「下一步」按钮才会从 disabled 变为 enabled
- 点击后进入确认/执行阶段

### 2.4 发布历史管理

在应用管理后台（`/ae/app_manage/{namespace}/publish_history`）查看发布历史：

#### 发布历史表格

| 列 | 说明 |
|----|------|
| 版本号 | 如 0.1.0、1.0.0 |
| 描述 | 更新说明文本 |
| 状态 | 发布中/已发布/已回滚 |
| 发布人 | 执行发布的操作人 |
| 申请时间 | 提交发布申请的时间 |
| 发布时间 | 实际发布完成的时间 |
| 操作 | 回滚/查看详情 |

### 2.5 发布后的状态变化

| 维度 | 发布前 | 发布后 |
|------|--------|--------|
| 应用状态 | 待发布 | 已发布 |
| 「访问」按钮 | disabled | enabled |
| 「分享」按钮 | disabled | enabled |
| 运行态可访问 | 否 | 是 |
| 应用上架 | 否 | 上架到飞书工作台 |
| 版本号 | 无 | 0.1.0（首次） |

## 三、平台业务流向分析

### 3.1 整体业务流

```
用户登录
  ↓
首页 Portal ──────────────────────────────────────────
  │ ├── 快速新建应用（5种方式）                        │
  │ ├── 热门模板推荐                                   │
  │ ├── 我的开发项目（管理/开发）                      │
  │ ├── 我的任务（待处理/抄送/已发起）                 │
  │ └── 学习中心 + 产品动态                           │
  ↓                                                    │
开发中心 ──────────────────────────────────────────   │
  │ ├── 应用列表（新建/管理/开发）                     │
  │ └── 共享库列表                                    │
  ↓                                                    │
应用构建器 (Builder) ──────────────────────────────── │
  │ ├── 页面设计（拖拽组件 → 配置属性 → 预览）         │
  │ ├── 数据建模（创建对象 → 定义字段 → 配置视图）     │
  │ ├── 流程编排（选触发器 → 拖拽节点 → 配置变量）     │
  │ ├── 云函数（编写代码 → 部署）                      │
  │ ├── 权限配置（创建角色 → 分配权限 → 设置成员）     │
  │ ├── 观测监控（事件追踪 → 链路分析）                │
  │ └── 集成管理（凭证 → 连接器 → API）               │
  ↓                                                    │
检查 → 提交 → 发布 → 上架 ──────────────────────────│
  ↓                                                    │
应用管理后台 ──────────────────────────────────────── │
  │ ├── 概览（运营报表）                               │
  │ ├── 环境信息                                       │
  │ ├── 发布历史（版本管理/回滚）                      │
  │ ├── 应用权限 / 数据管理 / 审批管理                 │
  │ ├── 审计日志                                       │
  │ ├── 运维监控（应用观测/监控设置）                  │
  │ └── 开放能力（MCP/Open API/数据共享）             │
  ↓                                                    │
流程中心 ──────────────────────────────────────────── │
  │ ├── 我的任务（处理审批任务）                       │
  │ ├── 效率分析                                       │
  │ └── 快捷入口（审批数据管理/交接管理）              │
  ↓                                                    │
应用中心 ──────────────────────────────────────────── │
  └── 已发布应用的使用入口                             │
```

### 3.2 开发态 vs 运行态分离

飞书 aPaaS 明确区分**开发态**和**运行态**：

| 维度 | 开发态 (Builder) | 运行态 (Runtime) |
|------|------------------|------------------|
| URL 域名 | `cmhk-try-dev3.aedev.feishuapp.cn` | `cmhk-try.feishu.cn` |
| 用户角色 | 开发者 | 业务用户 |
| 操作类型 | 构建/编辑/提交 | 查看/填写/审批 |
| 数据环境 | 开发环境数据 (lane=develop) | 生产环境数据 |
| 版本 | 开发中版本 | 已发布版本 |
| 页面来源 | 实时编辑的 schema | 已发布版本的快照 |

**关键设计原则**：
- 开发态的修改**不会直接生效**到运行态
- 必须经过「检查→发布」流程才能将变更同步到运行态
- 发布前，开发者可通过「预览」功能在开发态内查看效果
- 运行态用户只能看到已发布的版本

### 3.3 环境与版本模型

```
应用 (Application)
  ├── 命名空间 (namespace, 如 package_3625c5__c)
  ├── 开发环境 (develop lane)
  │   ├── 页面 (开发中版本 - 可实时编辑)
  │   ├── 对象 (开发中版本 - 可实时编辑)
  │   ├── 流程 (开发中版本 - 可实时编辑)
  │   ├── 权限 (开发中版本 - 可实时编辑)
  │   └── 云函数 (开发中版本 - 可实时编辑)
  ├── 沙箱环境 (sandbox)
  │   └── 用于测试验证（env=sandbox）
  └── 生产环境 (production)
      └── 已发布版本 (versioned snapshots)
          ├── v0.1.0 (首次发布 - 不可变快照)
          ├── v1.0.0 (第二次发布 - 不可变快照)
          └── ... (可回滚到任意历史版本)
```

**版本快照内容**：每次发布时，系统收集所有模块的当前开发态配置（页面 schema、对象定义、流程定义、权限规则、云函数代码），生成一个不可变的 JSON 快照。

## 四、交互体验与设计细节

### 4.1 构建器交互模式

#### 三栏布局

```
┌──────────────────────────────────────────────────────────┐
│  顶部工具栏：搜索 | 检查 | 访问 | 发布 | 智能助手 | 头像  │
├──────┬───────────────────────────────────┬───────────────┤
│ 左栏  │           中栏（画布）             │   右栏        │
│      │                                   │  （属性面板）   │
│ 资源  │     可视化编辑区域                 │              │
│ 管理  │     支持缩放、拖拽                 │  上下文感知   │
│ 器 +  │                                   │  随选中元素   │
│ 组件  │                                   │  变化         │
│ 面板  │                                   │              │
│      │                                   │              │
├──────┴───────────────────────────────────┴───────────────┤
│  底栏：错误检查 | 控制台 | 请求时间轴 | 性能（可折叠）     │
└──────────────────────────────────────────────────────────┘
```

#### 左侧导航（7大模块图标导航）

页面、数据、流程、云函数、权限、观测、集成 — 每个模块有独立的子导航菜单。

### 4.2 关键交互模式

#### 1. 异步操作 + 进度反馈

所有耗时操作都采用异步模式，显示进度百分比和阶段描述：
- 应用创建：40% → 70% → 100%（带阶段描述）
- 预检检查：30% → 80% → 100%
- 发布流程：进度跟踪
- 支持「后台运行」，不阻塞用户操作

#### 2. 变更追踪 (Change Tracking)

- 系统自动追踪所有开发态变更
- 记录：变更项、变更类型（新建/更新/删除）、变更人、最后变更时间
- 发布前生成完整变更清单
- 支持查看每个变更项的详情

#### 3. 预检机制 (Pre-publish Check)

- 发布前必须执行检查
- 检查覆盖所有模块
- 有问题必须修复后才能发布
- 检查结果有时间记录，支持重新检查

#### 4. 版本管理

- 语义化版本号（0.1.0 → 1.0.0）
- 每次发布生成不可变快照
- 支持版本回滚
- 版本号自动递增

#### 5. 模板驱动

所有创建操作都有模板支持：
- 应用创建：60+ 应用模板

### 6.2 架构更新建议

#### P0 — 必须立即对齐的核心缺失

**1. 应用发布流程 (Phase 9 — 当前严重缺失)**

飞书的发布流程是核心闭环：

```
开发态修改 → 检查(预检) → 填写版本号+更新说明 → 生成变更清单 → 发布 → 生成快照 → 上架运行态
```

需要实现：
- **ApplicationService.publish()** 方法 — 收集所有 objects/pages/processes/permissions 的当前开发态配置，生成 `publishedSnapshot` JSON
- **版本管理** — 版本号自增、发布历史记录、版本回滚
- **预检机制** — 发布前检查所有配置完整性（如页面是否绑定了不存在的对象）
- **变更追踪** — 记录每次开发态变更（谁、何时、改了什么）
- **发布向导 UI** — 版本号输入、更新说明、变更清单展示
- **发布历史页面** — 版本列表、状态、回滚操作

**2. 开发态/运行态环境隔离**

当前我方平台没有环境隔离，开发态修改直接生效。需要：
- 开发环境 (develop lane) vs 生产环境 (production) 数据隔离
- 发布操作将开发态配置快照同步到生产态
- 运行时 UI (runtime-ui) 只读取已发布版本
- 页面 getBySlug API 应返回已发布版本而非开发态

**3. 应用创建流程完善**

当前我方只有简单的创建弹窗。需要对齐：
- 应用图标选择器（预设图标 + 自定义上传）

model Application {

model AppVersion {

  appId         String

  createdAt     DateTime @default(now())

model ChangeLog {
