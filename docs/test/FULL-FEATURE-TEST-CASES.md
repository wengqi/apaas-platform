# 第一部分：用户操作角度测试用例

> 设计原则：以终端用户或搭建者的操作路径为主线，模拟真实使用场景，验证功能正确性和用户体验。

## TC-A 认证与登录

### TC-A-001 用户登录（正确凭证）

| 项 | 内容 |
|---|---|
| **前置条件** | 租户已创建，用户已注册且状态为 ACTIVE |
| **操作步骤** | 1. 访问 Studio 登录页 `/login`<br>2. 输入邮箱和密码<br>3. 点击登录 |
| **预期结果** | 登录成功，跳转到 `/apps` 应用列表页，页面显示用户名和头像，localStorage 存储 JWT token |

### TC-A-002 用户登录（错误密码）

| 项 | 内容 |
|---|---|
| **前置条件** | 用户已注册 |
| **操作步骤** | 1. 输入正确邮箱 + 错误密码<br>2. 点击登录 |
| **预期结果** | 登录失败，提示"邮箱或密码错误"，不跳转，不生成 token |

### TC-A-003 用户登录（不存在邮箱）

| 项 | 内容 |
|---|---|
| **操作步骤** | 输入未注册的邮箱 + 任意密码，点击登录 |
| **预期结果** | 登录失败，提示"邮箱或密码错误"（不暴露邮箱是否存在） |

### TC-A-004 用户登录（禁用账户）

| 项 | 内容 |
|---|---|
| **前置条件** | 用户状态为 DISABLED |
| **操作步骤** | 输入正确邮箱 + 正确密码，点击登录 |
| **预期结果** | 登录失败，提示账户已禁用 |

### TC-A-005 带租户标识登录

| 项 | 内容 |
|---|---|
| **操作步骤** | 1. 访问 `/t/{slug}/login`<br>2. 输入邮箱和密码登录 |
| **预期结果** | 登录成功，token 中包含正确的 tenantId |

### TC-A-006 未登录访问受保护页面

| 项 | 内容 |
|---|---|
| **操作步骤** | 未登录状态下直接访问 `/apps` |
| **预期结果** | 自动重定向到 `/login` 页面 |

### TC-A-007 退出登录

| 项 | 内容 |
|---|---|
| **前置条件** | 用户已登录 |
| **操作步骤** | 点击退出登录按钮 |
| **预期结果** | 清除 token，跳转到登录页，再访问受保护页面被重定向 |

### TC-A-008 Token 过期后访问

| 项 | 内容 |
|---|---|
| **前置条件** | 用户 token 已过期 |
| **操作步骤** | 携带过期 token 请求 API |
| **预期结果** | 返回 401，前端跳转到登录页 |

**业务场景**：搭建一个采购申请系统
