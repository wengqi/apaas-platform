## 二、发现的问题与修复（全部已修复并复验）

### 阻断级

**#3 搭建器搭建的表单页无法保存（G3 白名单缺 form 原生按钮类型）**
- 现象：amis-editor 中任何带提交按钮的表单页，保存时报「未知的 amis 组件类型 "submit"——是否想用 "select"?」，保存必失败（截图 26）。
- 根因：amis form 渲染时自动生成 `{type:'submit'}` 默认按钮；搭建器序列化画布必然携带；G3 白名单（amis-type-registry）漏掉 amis 原生 form actions 类型 `submit`/`reset`。错误消息中的编辑距离建议（submit→select）进一步误导。
- 业界参照：amis 官方 schema 的 form.actions 原生支持 submit/reset/button；飞书/钉钉表单搭建器的提交按钮为编辑器内建能力。
- 修复：白名单补充 `submit`/`reset`（amis-type-registry.ts）+ 回归单测；复验「页面已保存（服务端过 G3 校验）」（截图 60）。

### 高优先级

**#5 流程设计器「指定用户」要求手输用户 ID**
- 现象：审批节点审批人类型选「指定用户」后，需要手动输入用户内部 ID（cuid）才能配置（截图 35）；节点摘要也直接显示 ID（截图 41）。搭建者根本无法知道数据库 ID——连平台开发者都要去数据库查。
- 根因：配置面板未提供成员数据源；会签/或签的 approveUsers 数组字段此前在 UI 上完全无法配置（只能靠 API 写入）。
- 业界参照：飞书 aPaaS/钉钉审批的审批人配置均为**成员搜索选择器**（按姓名/邮箱搜索，头像+多选），ID 从不暴露。
- 修复：UserTaskConfigForm 接入 `usersApi.list()`（React Query 全局缓存共享）——单人模式=成员单选搜索选择器；会签/或签/依次=成员多选（写入引擎 approveUsers 数组），模式切换时已选人员自动迁移；节点摘要优先显示姓名缓存（assigneeName/assigneeNames），历史数据回退 ID。

**#6 发布历史「发布人」显示用户 ID**
- 现象：发布历史页发布人列显示 `cmurqrocs000axoiwyptnoy1l`（截图 45）。
- 修复：VersionHistory 接入用户列表建立 id→姓名映射；统一新增规范查询键 `qk.users()`（shared/stores）供成员选择器与显示名映射共用。

### 中优先级（数据录入逻辑）

**#7 提交表单让业务用户手选审批状态**
- 现象：合同提交表单中「审批状态」为必填下拉，选项含「已批准/已驳回」——提交人选「已批准」在业务逻辑上荒谬（截图 50b）。
- 业界参照：状态类字段是流程回写字段，在提交表单中应隐藏（飞书/钉钉做法），由流程节点写入。
- 修复：seed 提交页 schema 将 status 改为 `hidden` 控件携带默认值 `PENDING`（满足对象 required 校验），业务表单只剩干净的业务字段（复验截图 61）。

**#8 表单提交成功后无任何反馈**
- 现象：提交审批后无 toast、无跳转、表单不清空——用户无法确认是否成功。
- 修复：seed 提交按钮接入 amis 原生 `feedback` 成功弹窗（提交成功 + 下一步指引文案）+ `messages` 成功/失败提示（复验截图 62）。

**#9 审批弹窗双提交入口混淆**
- 现象：审批弹窗内审批页表单自带「提交」按钮，弹窗 footer 又有「批准/拒绝」——两个动作入口让审批人困惑（截图 53）。
- 修复：seed 审批页 schema 的意见表单 `actions: []`，footer 批准/拒绝为唯一动作入口。

**#10 权限调试「拒绝 + 记录可见」矛盾结果**
- 现象：权限调试对无规则目标返回「拒绝」，同时记录可见性显示绿色「记录可见」——结论矛盾让用户困惑（截图 58）。根因：可见性 count 查询语义是「记录是否存在且落在行级条件内」，与权限决策是两个独立维度。
- 修复：拒绝场景下记录可见性提示改为中性语义（「记录存在，但当前权限决策为拒绝；权限拒绝时该记录仍不可读取」），对齐 AWS IAM Policy Simulator 的 deny 场景说明模式。

### 低优先级（已顺手修复）

- **#1 登录页租户标识引导**：placeholder「留空则使用平台管理员登录」技术上正确（平台超管分支真实存在）但对租户用户误导——改为「租户用户必填（如 demo）；平台管理员可留空」。
- **#5b 对象列表字段数不刷新**：添加字段后左栏「5字段」不更新——FieldConfigDrawer 保存后补失效 `qk.appObjects`。
- **#6' 台账表格末列被挤压截断**：seed 列定义仅前两列固定宽度、其余自适应。
- **#13 状态列显示英文枚举**：seed 台账状态列接入 amis `mapping` 渲染器（map 属性），显示「审批中/已批准/已驳回」。
- **#4 API 名称语义**：应用自动生成前缀 `package_` → `app_`（语义与资源类型一致）；对象/页面/流程创建弹窗在填写显示名称后自动生成 `obj_/page_/flow_` 建议值（可修改），不再强制用户凭空起名。

### OCR 评审阶段追加发现

**#11（体系性，OCR 契约审查发现）UI 搭建的多人审批流程运行时失效**
- 现象：搭建器面板写入大写枚举（`SINGLE/COUNTERSIGN/OR_SIGN`），而流程引擎（user-task.executor/process-engine）与 G3 workflow 校验器只认**小写**（`single/countersign/or_sign/sequential`）。后果双重：① UI 搭建会签/或签流程在保存时被 G3 拒绝；② 历史绕过数据在运行时**静默退化为单人审批**（会签/或签聚合逻辑不触发）。
- 根因：R1.3 审批语义落地时 seed/引擎用小写契约，搭建器面板另行定义大写选项——两侧从未对齐，e2e 全绿因 seed 直写小写、UI 配置路径零测试覆盖（本轮用户视角实测+OCR 契约审查双重复核才暴露）。
- 修复：引擎与 G3 校验器读取侧统一 `.toLowerCase()` 归一化（三处），两侧历史数据零迁移兼容；补大小写双向回归单测（G3 28/28）。
