# aPaaS 平台测试用例库（活文档）

> **状态**：生效中 · 活文档
> **版本**：v1.0 · 2026-10-07 建立
> **来源**：148 条基线自 `docs/testing/QA-FULL-REPORT-2026-10-06.md` §九（TC-001~133）与 §10.10（TC-134~148）逐条提炼；前置/步骤/预期的标准化展开以该报告原文 + `docs/testing/QA-TEST-PLAN-PROMPT.md` 底册与矩阵描述为依据。
> **用途**：可持续维护的标准测试用例库——开发迭代中按维护规约即时补充/修订，测试验证与里程碑执行时按本库取用例。
> **配套**：测什么/测到什么粒度（标准与功能清单 SSOT）= `QA-TEST-PLAN-PROMPT.md`；改了什么跑什么 = `docs/knowledge-base/TEST-JOURNEY-MAP.md`；执行结果（实际/结论/证据）记录于当次 `docs/testing/QA-REPORT-*.md`，**不入本库**。

## 维护规约（强制）

1. **即时同步**：功能迭代、缺陷修复、契约变化必须在**同一提交内**依据最新项目信息补充或修订对应用例——标准清单加一格（QA-TEST-PLAN-PROMPT.md）→ 用例库加一条（本文件）；新回归锚点转为正式用例。更新要即时，不得欠账、不得遗漏。
2. **编号只增不复用**：新用例从 **TC-149** 起按所属域分组追加；永不复用、永不改写既有编号语义。
3. **只写"应然"**：本库只维护 编号/标题/优先级/前置/步骤/预期/自动化状态；不携带"实际结果/结论"（那是执行快照，归 QA 报告）。
4. **已修复缺陷的用例写修复后语义**（如 D-002 修复后预期 400），历史失败结果留在原报告；已知未修缺陷在备注标注"已知缺陷"。
5. **优先级标注规则**：P0=核心主链路（登录/建模→提交→审批→回写→发布渲染，断即平台不可用）；P1=主要功能负向校验与已修复缺陷回归；P2=一般功能点；P3=文案提示类。基线优先级为 v1.0 人工标注，使用中可修订。
6. **环境与账号事实**以 `QA-TEST-PLAN-PROMPT.md` 第一节为准（入口 5173/5174/3000、账号与密码、种子应用禁删改、新资源一律 `qa_` 前缀、auth 限流 10/min——API 登录+token 复用，勿与 e2e 并发撞限流）。
7. **分组**：A~K 沿用源报告 §九；L 为纪律红线补测轮整批（保持批次溯源）。TC-149 起归入所属域分组 A~K。

**用例格式**：`编号 | 用例标题 | 优先级 | 前置条件 | 测试步骤（含测试数据） | 预期结果 | 自动化 | 备注`
